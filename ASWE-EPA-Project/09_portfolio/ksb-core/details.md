# Portfolio - Core Evidence

## What the Portfolio Is About

The Portfolio demonstrates breadth across different types of work, projects, and contexts. While the Capstone shows depth (one major project), the Portfolio shows versatility: multiple projects, different technologies, different leadership contexts, different business challenges.

## What Makes a Strong Portfolio

**Breadth Examples:**
- 3–5 different projects/initiatives (not all the same type)
- Different technologies or domains (not all backend, not all frontend)
- Different leadership contexts (individual contributor, tech lead, mentor)
- Different business challenges (revenue, cost, compliance, scale)

**Example Portfolio:**
- Project 1: Build a customer-facing web app (revenue focus)
- Project 2: Migrate legacy system to cloud (cost + compliance focus)
- Project 3: Lead team through technical transformation (leadership focus)
- Project 4: Architect high-scale system (performance focus)
- Project 5: Open-source contribution or side project (learning focus)

**Not Suitable:**
- Five small bug fixes (not substantial)
- Five similar projects (no breadth)
- Only documentation or theoretical work (no execution)

## How Portfolio Evidence Works

**Structure:** One core folder (ksb-core) with three files:
1. `details.md` - What the portfolio demonstrates
2. `evidence-submitted.md` - What you showed examiners initially
3. `evidence-new.md` - Additional evidence for higher grade

**Key Difference from Capstone:**
- Capstone: Integration across KSBs in ONE major project
- Portfolio: Breadth across MULTIPLE different projects

## Related Files

- `evidence-new.md` - Strengthening evidence for higher grade
