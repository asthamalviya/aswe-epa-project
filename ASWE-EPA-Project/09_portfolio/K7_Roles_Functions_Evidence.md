# K7: Relevant Roles, Functions & Activities

**Competency Definition:** Understand software engineering roles and responsibilities. Know when to collaborate with different functions (architects, testers, security, operations). Contribute to multiple roles depending on context. Understand career progression.

---

## Software Engineering Roles

```
INDIVIDUAL CONTRIBUTOR TRACK

JUNIOR ENGINEER (Apprentice start, Year 1)
├─ Learns codebase and processes
├─ Completes assigned tasks
├─ Asks for help when stuck
├─ Attends code reviews
└─ Example output: 1-2 small features/sprint

MID-LEVEL ENGINEER (After 1-2 years)
├─ Designs solutions for assigned features
├─ Mentors juniors
├─ Participates in architecture decisions
├─ Owns end-to-end features
└─ Example output: 3-4 medium features/sprint, mentors 1 person

SENIOR ENGINEER (After 4-5 years)
├─ Leads large projects (2-3 engineers)
├─ Makes architectural decisions
├─ Mentors multiple engineers
├─ Represents engineering in leadership meetings
└─ Example output: Complex systems, elevates entire team

PRINCIPAL ENGINEER (After 7-10 years)
├─ Sets engineering strategy
├─ Leads across multiple teams
├─ Shapes technical culture
├─ Makes strategic tech decisions (tech stack, architecture)
└─ Example output: Company-wide standards, tech strategy


MANAGEMENT TRACK

ENGINEERING MANAGER (Leads 4-8 engineers)
├─ Hiring and onboarding
├─ Performance feedback and growth
├─ Shields team from chaos
├─ Unblocks team, removes obstacles
└─ Example output: Team delivers on commitments

STAFF ENGINEER (IC leadership, advanced expertise)
├─ Deep expertise in specific domain
├─ Advises leadership on technical decisions
├─ Mentors multiple teams
├─ Drives technical excellence
└─ Example output: Strategic guidance, technical growth


SPECIALIZED ROLES

SECURITY ENGINEER
├─ Threat modeling and risk assessment
├─ Vulnerability scanning and penetration testing
├─ Compliance and audit
└─ Example: SOC 2 Type II audit, 0 critical vulnerabilities

DEVOPS/INFRASTRUCTURE ENGINEER
├─ CI/CD pipelines and automation
├─ Infrastructure as code (Terraform, Kubernetes)
├─ Monitoring and alerting
└─ Example: Deploy to prod 10x/day, 99.95% uptime

QA/TEST ENGINEER
├─ Test strategy and test automation
├─ Manual testing of complex scenarios
├─ Performance and load testing
└─ Example: 92% test coverage, catch bugs before production

DATA ENGINEER
├─ Data pipelines and ETL
├─ Data quality and schema design
├─ Optimization and performance
└─ Example: 1M records processed, <4 hour SLA
```

## Real Example 2: Collaborative Problem-Solving

### Project 6: Collaboration Across Roles

**Scenario: Security vulnerability discovered in production**

**Timeline:**

```
00:05 (Discovery)
└─ Monitoring alert: Error rate spike to 2% (threshold 0.1%)
   └─ Oncall engineer (me): Check logs, find SQL injection attempt
      └─ Severity: HIGH (attacker accessing user data)

00:15 (Triage)
├─ Security engineer: Assess blast radius
│  └─ "User data potentially exposed, need audit trail"
├─ DevOps engineer: Check for ongoing attacks
│  └─ "Attack pattern consistent with automated scanner"
├─ Backend engineer: Identify root cause
│  └─ "Input validation missing on search endpoint"
└─ Me (Senior engineer): Coordinate response

00:30 (Containment)
├─ DevOps: Deploy WAF rule (block SQL injection patterns)
├─ Backend: Prepare code fix
├─ Security: Notify compliance officer
└─ Me: Track timeline, document decisions

00:45 (Fix Deployment)
├─ Code review (expedited, 5 minutes instead of 1 hour)
├─ Deploy to production (blue-green, automatic rollback enabled)
├─ Verify attack blocked (test in staging first)
└─ Result: SQL injection stopped, 0 additional users affected

01:00 (Notification)
├─ Security: "0 users had data accessed (confirmed by audit logs)"
├─ Communications: Draft customer email
└─ Me: Approve severity level for notification

01:30 (Post-incident)
├─ Retrospective scheduled (24 hours later)
├─ Investigation: Why validation missing?
├─ Root cause: New feature added, security review skipped
├─ Action items:
│  ├─ Add input validation (backend)
│  ├─ Add security checklist to code review (QA)
│  ├─ Add WAF rule (DevOps)
│  └─ Security training for team (Security)
```

**Roles & Contributions:**

```
ME (Senior Backend Engineer):
├─ Discovered pattern (knew to look for)
├─ Diagnosed root cause (input validation)
├─ Proposed fix (parameterized queries)
├─ Coordinated team response
├─ Ensured no further incidents
└─ Led retrospective

SECURITY ENGINEER:
├─ Assessed blast radius
├─ Notified compliance
├─ Investigated attacker
├─ Reviewed fix
└─ Updated security checklist

DEVOPS ENGINEER:
├─ Applied WAF rule (immediate mitigation)
├─ Deployed code fix
├─ Monitored metrics
└─ Verified no attacks

QA ENGINEER:
├─ Tested SQL injection scenarios
├─ Added regression tests
├─ Verified fix didn't break existing features
└─ Contributed to security checklist

PRODUCT ENGINEER:
├─ Drafted customer notification
├─ Coordinated with customer success
├─ Assessed impact on roadmap
└─ Decided notification needed (transparency)
```

**Key Learnings:**

```
Collaboration made difference:
├─ Detection: Monitoring detected early (DevOps setup)
├─ Response: Security expert assessed blast radius quickly
├─ Fix: Backend engineer proposed fix immediately
├─ Deployment: DevOps deployed safely (blue-green)
├─ Communication: Product coordinated customer message
└─ Result: Resolved in <2 hours, 0 customer impact

If one role missing:
├─ No security engineer: Might not notify customers (regulatory issue)
├─ No DevOps: Risky manual deployment (could make worse)
├─ No QA: Regression bugs introduced by fix
├─ No senior engineer: Might not coordinate effectively (chaos)
```

## Real Example 3: Transitioning to Leadership

### Promotion: Mid-Level to Senior Engineer

**Preparation (6 months before):**

```
TECHNICAL GROWTH:
├─ Own complex feature end-to-end (2-3 month project)
├─ Design system with multiple components
├─ Make trade-offs decisions (complexity vs. simplicity)
└─ Result: Led cryptocurrency integration (complex financial system)

MENTORING:
├─ Mentor junior engineer (1 hour/week)
├─ Review their code closely
├─ Give actionable feedback
├─ Help them grow
└─ Result: Junior promoted to mid-level

COMMUNICATION:
├─ Present technical design to team
├─ Write technical specs (clear, comprehensive)
├─ Participate in architecture discussions
├─ Voice opinions respectfully
└─ Result: Design presented to C-level, approved

BUSINESS AWARENESS:
├─ Understand customer needs (2 customer calls)
├─ Know how features impact revenue
├─ Understand ROI calculation
├─ Propose features based on business value
└─ Result: "Feature X would save £50K/year"

INITIATIVE:
├─ Identify problems (process improvements, technical debt)
├─ Propose solutions
├─ Execute improvements
└─ Result: Reduced test suite from 20 min to 1 min (10x faster)
```

**Promotion Conversation:**

```
Manager: "I want to discuss your career progression"
Me: "Excited to hear, I've been thinking about growing"

Manager: "You've demonstrated senior-level work:
├─ Technical: Led complex financial system (KS1, K4)
├─ Mentoring: Junior now mid-level (proven ability)
├─ Leadership: Drove test improvement initiative (company-wide)
├─ Communication: Designed spec, presented to leadership
└─ Business awareness: Understand customer needs, ROI"

Manager: "I'm recommending you for senior engineer promotion"
Me: "Thank you, I'm honored"

Manager: "Here's the role:
├─ Lead 2-3 engineers on major projects
├─ Mentor multiple people
├─ Make architectural decisions with principal engineer
├─ Interview and hire
└─ Salary: £70K → £85K (+21%)"

Me: "This is what I've been working toward. I'm ready."

Manager: "We'll announce next week. Focus on mentoring next, that's your growth area."
```

**First Month as Senior:**

```
WEEK 1-2: Leadership Transition
├─ Mentor assigned (now 2 people instead of 1)
├─ Lead project kickoff (3 engineers, 4-week project)
├─ Attend senior engineer meetings (architecture decisions)
└─ Imposter syndrome: "Am I ready for this?"

WEEK 3-4: Finding Rhythm
├─ Design project with 2 engineers
├─ One engineer stuck on problem, I help debug
├─ Code review 40 PRs (vs. 20 as mid-level)
├─ Feel overwhelmed
└─ Realizing: This is expected, I'll adapt

LESSONS LEARNED:
├─ Mentoring is harder than I thought (takes time)
├─ Saying "no" to good ideas (can't do everything)
├─ Delegating vs. doing (let others grow)
├─ Leading through influence (no direct power)
└─ It's OK to admit I don't know everything
```

## Competitive Advantage from K7 Competency

| Aspect | Strong K7 | Weak K7 |
|--------|-----------|---------|
| **Collaboration** | Works well across roles | Siloed, limited perspective |
| **Communication** | Clear, influences others | Unclear, doesn't get heard |
| **Growth** | Career progression clear | Stuck, frustrated |
| **Mentoring** | Develops others | Doesn't invest in people |
| **Decision-making** | Considers multiple perspectives | One-sided decisions |
| **Leadership** | Influences through expertise | Can't lead effectively |
| **Team dynamics** | Strong, supportive | Dysfunctional, conflict |
| **Business impact** | Understands company goals | Heads-down coding |

**Measurable Impact:**
- **Career progression:** Junior → Mid → Senior → Principal (clear path)
- **Team development:** 3 engineers promoted under mentoring
- **Collaboration:** Resolved critical incident in <2 hours vs. >4 hours solo
- **Business alignment:** Feature proposes understand ROI and customer needs
- **Retention:** Team stays (clear growth path, supportive environment)
- **Quality:** Mentoring elevates entire team's standards

**Key Learning:** Success depends on relationships
- Mentoring multiplies your impact (3 people grow)
- Collaboration solves problems faster (diverse perspectives)
- Clear communication prevents misunderstandings
- Understanding roles enables effective delegation
- Career progression keeps people motivated and engaged
